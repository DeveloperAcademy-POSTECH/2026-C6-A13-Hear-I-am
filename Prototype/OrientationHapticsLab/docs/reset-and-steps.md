# 리셋 지연과 걸음 수 미갱신 개선

## 확인 범위

진동 모드에서 0° 리셋 후 앱이 멈추고 걸음 수가 계속 0이라는 보고를 기준으로 코드를 점검했다. 초기 개선 시점에는 실제 아이폰의 멈춤 당시 호출 스택이나 실행 시간을 수집하지 못했다. 이후 실기기 첫 실행 크래시의 호출 스택을 확보했으며 [후속 수정 기록](startup-crash.md)에 원인과 수정 내용을 정리했다. 아래는 코드에서 확인한 문제 경로이며, 특정 기기에서 발생한 멈춤의 단일 원인을 확정한 결과는 아니다.

## 원인 후보와 변경

| 경로 | 기존 문제 | 적용한 변경 |
| --- | --- | --- |
| 진동 준비 | 리셋마다 엔진을 버리고 UI 스레드에서 동기 시작을 기다림 | 별도 actor에서 비동기 시작, 평상시 엔진 재사용, 신호만 교체 |
| 장치 응답 지연 | 장치 준비/재생 완료 지연을 화면 처리와 함께 기다릴 가능성 | 3초 내 응답·완료가 없으면 해당 신호 취소, 측정 유지 |
| 로그 저장 | 리셋마다 전체 로그 JSON 변환과 파일 쓰기를 UI 스레드에서 수행 | 별도 actor에서 저장, 저장 순번으로 오래된 결과의 덮어쓰기 방지 |
| 방향 자료 전달 | 60Hz 자료가 UI 큐에 쌓이고 지연된 자료로 기준 무효화 | 30Hz 별도 큐에서 처리, 최신 자료 하나만 전달, 개별 지연 자료 무시 |
| 방향 기준 무효화 | 기준 무효화가 걸음 사이클까지 종료해 이후 갱신 차단 | 방향만 무효화하고 걸음 집계는 유지, 방향 누락 구간은 좌표 불확실성으로 처리 |
| 권한 팝업 | 일시적인 inactive 상태에서 전체 측정을 종료 | inactive에서는 신호만 중단, 실제 background 진입 시 사이클 종료 |
| 걸음 자료 검증 | 선택 항목인 거리의 이상값·보정이나 같은 시각의 자료 때문에 정상 걸음까지 거부 | 유효한 누적 걸음 반영, 거리만 보류하고 불확실성 표시 |
| 걸음 콜백 지연 | 실시간 콜백이 없으면 화면도 계속 초기값 | 별도 actor에서 센서 호출, 수신이 없을 때 3초 간격으로 시스템의 처리된 자료 조회 |

진동의 오래된 콜백은 새 신호나 종료된 화면을 되살릴 수 없다. 전체 화면 색상은 재생 시작이 수락된 뒤 표시한다. 로그의 신호 이력은 앱에 접수된 요청이며 실제 진동 체감의 증거는 아니다.

걸음 수는 시스템이 이미 처리한 자료만 사용한다. 보조 조회가 센서의 처리 지연을 없애거나 매 걸음을 즉시 검출한다는 의미는 아니다. 리셋 직후의 이전 사이클 최종 조회에도 아직 처리되지 않은 걸음이 빠질 수 있다.

## 자동 검증

2026-10-07, Xcode / iOS 26.3 시뮬레이터:

- 계산 모듈 30개 통과: 거리 보정 시 걸음 유지, 같은 시각의 0→7걸음 갱신 포함
- 앱 테스트 32개 통과: 늦은 진동 응답, 취소된 신호 콜백, 응답 시간 초과, 방향 자료 지연·자세 오류, 권한 팝업, 반복 리셋 포함
- 시뮬레이터 빌드 성공
- 기존 로그 저장 형식과 사용자 설정 유지

이 테스트는 앱의 처리 흐름을 검증한다. 실제 진동 드라이버의 응답 시간과 허리 착용 시 보행 인식률은 미측정이다.

## 아이폰에서 남은 확인

1. 진동 모드로 첫 실행과 재실행 각각 리셋 10회. 리셋 직후 각도 변화, 설정·중지 버튼 반응, 신호 종료 여부를 기록한다.
2. 최초 동작 및 피트니스 권한 팝업에서 허용한 뒤 다시 리셋하지 않고 7걸음을 걷는다. 표시 값과 마지막 수신 시각을 0초·5초·15초에 기록한다.
3. 잠깐 기기를 눕히거나 방향 자료를 잃은 뒤 걸음 집계가 유지되는지 확인한다. 방향 신호는 기준을 다시 잡기 전까지 중단되어야 한다.
4. 7걸음 이후 리셋하고 새 사이클 2걸음. 이전 값은 로그에, 새 값은 현재 화면에 분리되는지 확인한다.
5. 앱 전환·화면 잠금 후에는 사이클이 종료되고 복귀 시 재리셋이 필요한지 확인한다.

멈춤이 재발하면 Xcode에서 실행을 일시 정지해 메인 스레드 호출 스택을 확보하고, Instruments의 Hangs/Time Profiler로 오래 걸린 호출을 확인한다. 권한 거부·실기기 센서 오류·착용 조건은 이 코드 수정만으로 판정할 수 없다.

## 근거

- [Apple: CHHapticEngine.start()](https://developer.apple.com/documentation/corehaptics/chhapticengine/start()) — 동기 호출은 현재 스레드의 후속 이벤트 처리를 막는다.
- [Apple: CMPedometer.startUpdates](https://developer.apple.com/documentation/coremotion/cmpedometer/startupdates(from:withhandler:)) — 시작 시점부터 처리된 보행 자료를 비동기로 전달한다.
- [Apple: CMPedometer](https://developer.apple.com/documentation/coremotion/cmpedometer) — 처리된 걸음 자료 조회와 권한 확인 API.
