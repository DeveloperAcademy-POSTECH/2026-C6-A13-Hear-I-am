# StageVision iPhone · iPad MVP

ARKit으로 무대 바닥을 확보하고, 스태프가 실제 경계를 조준해 비정형 무대 지도를 만드는 SwiftUI 앱입니다. 한 Xcode 프로젝트·앱 타깃으로 iPhone과 iPad를 지원하며 iOS/iPadOS 26.2 이상이 필요합니다.

## 실행

1. `StageVision_iphone.xcodeproj`을 열고 `StageVision_iphone` 스킴을 선택합니다.
2. 연결한 iPhone/iPad를 선택하고 실행합니다. 실기기 설치에는 Signing & Capabilities의 개발 팀 설정이 필요할 수 있습니다.
3. `무대 지도` 탭에서 스캔합니다. LiDAR가 없는 ARKit world tracking 지원 기기도 사용할 수 있습니다. LiDAR·RoomPlan 지원 여부는 스캔 화면에서 표시합니다.
4. 시뮬레이터나 AR 미지원 기기에서는 `2D 편집 예제 열기`로 편집·위험구역·저장을 확인할 수 있습니다. 예제 JSON은 `quality.source = demo-not-measured`로 구별됩니다.

기존 RoomPlan 바닥 크기 측정, 직사각형 크기 조정, 네 방향 위험구역 및 무용수 시작 위치 기능은 `기존 직사각형` 탭에 보존했습니다. 기존 RoomPlan 스캔은 LiDAR 기기에서만 동작하며 새 다각형 지도와는 별개입니다.

## 스캔 → 편집 → 저장

1. **무대 정보:** 이름과 장소를 입력하고 `무대 스캔 시작`을 누릅니다.
2. **바닥 확정:** 바닥을 천천히 비춥니다. 카메라보다 낮은 수평면 중 면적이 큰 후보부터 민트색으로 표시합니다. 무대와 객석 바닥이 다르면 `다른 바닥 후보`로 선택한 뒤 `이 바닥 확정`을 누릅니다. 테이블이나 소품을 바닥으로 선택하지 않도록 확인하세요.
3. **원점:** 무대 앞쪽 중앙 또는 기준점을 중앙 조준점으로 가리키고 원점으로 지정합니다.
4. **앞 방향:** 카메라를 객석 방향으로 향하고 `이 방향을 무대 앞쪽으로 설정`을 누릅니다. 수직 방향에 가까우면 설정을 차단합니다.
5. **경계 입력:** 무대 안쪽에서 한 방향으로 돌며 모서리를 조준하고 `경계점 추가`를 누릅니다. 곡선은 여러 점으로 기록합니다. 카메라 위에 점과 선, 시작점까지의 거리가 표시됩니다. `실행 취소`는 마지막 점을 제거하고 `전체 초기화`는 바닥·원점·방향·점 모두를 초기화합니다.
6. **폐합:** 시작점을 다시 찍지 않고, 최소 3점에서 `경계 닫기`를 누릅니다. 마지막 선분까지 검사한 뒤 2D 화면으로 이동합니다.
7. **2D 편집:** 점을 드래그하거나 점 선택 후 화살표로 5cm씩 이동합니다. 선분을 터치하거나 구간 선택 메뉴로 선택하고 중간에 점을 추가할 수 있습니다. 선택 점 삭제, 실행 취소(최근 50개 변경), 원본 경계로 초기화를 지원합니다. 점 이동 중 위험영역을 숨기고 편집 완료 후 재계산합니다.
8. **앞 방향 수정:** 구간을 선택한 뒤 `이 구간을 무대 앞쪽·원점으로`를 누르면 구간 중점이 원점, 다각형 바깥쪽 법선이 객석 방향이 됩니다. 경계와 원본 경계, 기준점, 시작 위치 및 AR 변환도 함께 갱신됩니다. `앞/뒤/좌/우/기타` 분류는 구간 이름이며 좌표를 회전하지 않습니다.
9. **위험구역:** 각 S1…Sn 구간에서 활성 여부와 1.0m/1.5m를 선택합니다. 기본값은 전 구간 활성, 1.0m입니다. 오목한 무대에서도 실제 다각형 내부에만 주황색으로 표시합니다.
10. **시작 위치:** 해당 모드를 켜고 평면도 내부를 터치합니다. 위험구역에 있으면 경고합니다. 자동 위치 추적은 하지 않습니다.
11. **저장:** `JSON 저장`은 앱의 `Documents/StageMaps/<stageId>.json` 및 `latest.json`에 원자적으로 기록합니다. 다음 앱 실행에서 마지막 지도를 읽습니다. 같은 지도의 재저장은 해당 파일을 갱신합니다. `JSON 내보내기 / 파일에 저장`은 시스템 파일 저장 창을 엽니다. 편집은 명시적으로 저장해야 합니다.

## 좌표·기하 규칙

- 단위 m, 원점 `[0,0,0]`, +X 무대 오른쪽, +Y 무대 앞에서 뒤쪽, +Z 위쪽, 바닥 Z=0.
- `floorPolygon`과 `originalFloorPolygon`은 `[X,Y]` 배열입니다. 마지막 점을 중복 저장하지 않으며 마지막 선분이 0번 점으로 연결됩니다.
- `coordinateSystem.stageToARWorld`는 **열 우선(column-major) 4×4 행렬**입니다. 열은 순서대로 오른쪽, 뒤쪽, 위쪽, AR 월드의 원점입니다. `world = matrix × [X,Y,Z,1]`. 촬영 당시 ARSession에만 유효하며 다른 기기나 새 세션에서 재위치할 수 있다는 뜻은 아닙니다. 예제에는 행렬이 없습니다.
- `originalFloorPolygon`은 입력 당시의 모양을 보존합니다. 좌표계 재설정 시 원본도 같은 좌표계로 변환합니다.
- ARKit `existingPlaneGeometry` 수평 raycast 결과가 확정 높이 ±8cm 안에 있을 때 사용합니다. 다른 높이의 결과는 버리고, 실패 시 광선과 확정 높이의 가상 평면을 교차합니다. 저장 높이는 항상 확정 높이에 투영합니다.
- 가상 교차는 전방·아래 방향, 광선의 수직 성분 < −0.05, 거리 ≤20m일 때만 허용합니다. 카메라가 바닥보다 5cm 이상 위에 있어야 합니다.
- 최대 128점, 점 간 최소 5cm, 면적 0.01m² 이상, 좌표 ±200m 범위로 제한합니다. 중복·일직선 퇴화·되돌아 겹침·비인접 선분의 교차와 접촉을 검사합니다. 2D의 잘못된 편집은 빨간 선으로 표시하고 수정/실행 취소할 수 있지만 저장을 차단합니다. 자동 단순화로 원본 경계를 바꾸지 않습니다.
- 위험영역은 **선택 선분까지의 거리 ≤설정 폭인 영역 ∩ 무대 내부**입니다. 단순 다각형을 삼각 분할한 뒤 둥근 끝을 가진 거리 영역과 교차해 조각으로 저장합니다. 반원은 24개 선분으로 근사합니다(1.5m에서 최대 약 3.3mm의 현 근사 차이). 직선부 폭은 정확히 설정값입니다.
- `riskZones[].polygons`는 해당 구간의 조각 목록입니다. 모든 활성 구간의 조각을 **합집합**으로 해석해야 합니다. 조각 면적을 단순 합산하면 겹침이 중복 계산됩니다. 2D는 하나의 fill path로 겹침을 동일한 색으로 표시합니다. 하나의 정규화된 inset/안전영역 polygon을 생성하지는 않습니다.
- 점 삭제 시 합쳐지는 두 선분의 위험 활성은 OR, 폭은 큰 값을 사용합니다. 점 삽입 시 원래 선분 설정을 두 구간에 복제합니다.

## JSON 품질 정보

`StageMap.swift`가 버전 1 스키마를 정의합니다. 이름·장소·시각·버전·단위·좌표계·원본/편집 경계·구간 분류/위험 설정·위험 다각형 조각·기준점·수동 시작 위치·품질 정보가 포함됩니다.

- `boundaryUncertaintyMeters`: 현장 오차 모델이 없으므로 미측정(nil, JSON 필드 생략). 0m 오차로 해석하면 안 됩니다.
- `virtualPlanePointIndexes`: **originalFloorPolygon**의 가상 평면 입력 인덱스입니다. 2D 점 추가/삭제 후에도 원본 기준입니다.
- `unverifiedSegmentIndexes`: 현재 경계에서 가상 교차가 포함된 구간 또는 5m 초과 구간. 경계를 편집하면 전체 구간을 재확인 대상으로 표시합니다.
- `trackingInterruptionCount`: 캡처 중 정상 상태에서 추적이 저하된 횟수입니다.
- `manuallyEdited`: 2D에서 기하/좌표계가 수정됐는지 표시합니다.

## 검증 명령

프로젝트 루트에서:

```sh
xcodebuild -project StageVision_iphone/StageVision_iphone.xcodeproj \
  -scheme StageVision_iphone -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/StageVisionDerivedData CODE_SIGNING_ALLOWED=NO build

xcrun swiftc -module-cache-path /tmp/stagevision-swift-cache \
  StageVision_iphone/StageVision_iphone/StageMap/StageGeometry.swift \
  StageVision_iphone/StageVision_iphone/StageMap/StageMap.swift \
  StageVision_iphone/StageVision_iphone/StageMap/StageMapStore.swift \
  StageVision_iphone/Tests/StageMapCoreTests.swift -o /tmp/stagevision-core-tests
/tmp/stagevision-core-tests

git diff --check
```

호스트 Swift 테스트는 직사각형·오목/별 모양 다각형·반대 winding·선분 겹침/접촉·퇴화·위험구역 내부 clipping/폭·가상 광선 교차·좌표 변환·JSON 왕복·잘못된 저장 차단·삽입/삭제/방향 설정과 실행 취소·저장 복원/손상 파일 처리를 검증합니다. 앱 타깃의 소스와 동일한 파일을 컴파일하며 테스트 소스는 앱 타깃 밖에 있습니다.

2026-09-29 검증 결과: generic iOS device 및 generic iOS Simulator 빌드 성공(서명 제외), 호스트 테스트 263개 통과, `git diff --check` 통과. iPhone 17 Pro 시뮬레이터에서 시작 화면·비정형 평면도를, iPad Pro 11-inch 시뮬레이터에서 나란한 패널·점 드래그/삽입/삭제·1.5m 변경·저장/재실행 복원·파일 앱 JSON 내보내기를 확인했습니다. 저장 JSON과 내보낸 JSON의 경계 6점 및 첫 구간 폭 1.5m를 직접 검사했습니다. 실제 카메라/AR 동작과 측정 정확도는 아직 실기기에서 검증하지 않았습니다.

## 실기기 체크리스트

- iPhone/iPad 세로·가로에서 조준점과 실제 입력 위치가 일치하는지, 회전 후 버튼이 safe area 안에 있는지.
- 카메라 권한 허용/거절, 무대와 객석의 높이 차이, 복수 수평면에서 올바른 바닥 선택.
- 무대 끝 메시가 없는 부분에서 가상 교차 표시와 경계 좌표가 올바른지.
- 같은 경계를 두 번 기록해 원점·앞 방향·점 좌표·폐합 오차 비교. 실제 거리와 1.0m/1.5m 밴드 비교.
- 어두운 바닥·빠른 이동에서 입력 차단과 정상 추적 복귀 확인. 백그라운드/세션 중단 시 초기화 안내 확인.
- 비정형/오목한 경계 폐합, 교차 차단, 2D 드래그·추가·삭제·실행 취소·방향 변경.
- 매우 좁은 무대에서 전체가 위험구역으로 표시되는지, 각 선분 활성/폭이 독립적인지.
- 저장 후 강제 종료/재실행, 파일 앱 내보내기, JSON의 축·행렬·구간 인덱스 확인.
- 기존 직사각형 탭의 RoomPlan 스캔과 시작 위치 기능 회귀 확인.

## 현재 한계

단일 연속 세션의 수동 경계 MVP입니다. 바닥 확정은 작업자 판단이며 자동 의미 분류나 경계 자동 검출은 하지 않습니다. AR drift와 측정 정밀도는 현장 검증이 필요합니다. 일시적인 tracking 저하에서는 입력을 잠시 중지하지만 세션 중단/백그라운드/AR 오류는 전체 재스캔을 요구합니다.

위험구역은 2D에서 설정·표시합니다. 편집 후 AR 재투영, 곡선 연속 기록, 완전한 polygon inset/union과 작은 안전영역 제거, 다중 구역 정합, 마커·ARWorldMap 재위치, 오차 보정, 외부 JSON 가져오기 및 저장 지도 목록은 후속 범위입니다. 저장 파일은 공유할 수 있지만 이 MVP에는 버전 관리 기능이 없습니다.

## 사람 감지 · LiDAR / 시뮬레이션

**사람 감지** 탭에서 시작합니다. 기존 무대 지도·직사각형 기능과 독립적인 기능이며, 저장된 무대 지도와 좌표를 정합하지 않습니다.

- **LiDAR 실측:** 후면 카메라로 몸통이 보이는 여러 사람을 Vision 2D body pose로 찾고 ARKit `sceneDepth`와 `personSegmentation`을 결합합니다. 정지한 사람도 감지합니다. 두 frame semantics를 함께 지원하는 LiDAR iPhone/iPad가 필요합니다. 카메라 권한 거부 시 설정 바로가기를 제공합니다.
- **시뮬레이션:** 센서를 사용하지 않는 정지 인물 1명과 이동 인물 2명의 예제입니다. LiDAR 미지원 기기·시뮬레이터에서는 자동으로 시작합니다. 기본 반경 4m에서 2명, 5m로 늘리면 3명이 보입니다. 데이터는 실제 측정값이 아니라고 화면에 표시합니다.
- **화면:** 3D 사람 모형 / 평면도 전환, 1~5m 반경(0.5m 간격), 인원·최근접 거리, 사람별 번호·정지/이동 상태·추정 속도·좌우/앞/높이차, 카드 또는 평면도 인물 선택, 일시 정지·재시작을 제공합니다. 3D 모형의 키와 걷기 애니메이션은 설명용이며 실제 관절·키·바닥 검출 결과가 아닙니다.
- **좌표 기준:** 거리 = 카메라 광학 중심에서 몸통 표면 대표점까지의 3D 직선 거리. 좌우·앞은 현재 카메라 방위에 맞춘 중력 기준 수평 좌표이고, 높이차는 카메라 대비 몸통 높이입니다. 범위는 직선 거리로 필터링하므로 평면도상의 수평 반경과 경계가 다를 수 있습니다. 전방만 표시하며 카메라 밖·뒤쪽 사람을 탐지하는 360도 레이더가 아닙니다.
- **깊이 처리:** root/neck 신뢰도 >0.45인 몸통 중점 주변 5×5 깊이 패치에서 사람 마스크와 high confidence인 픽셀만 사용합니다. 유효 샘플 5개 이상, 0.2~6m, 중앙절대편차 ≤0.12m 조건을 적용합니다. 이 수치는 필터 기준이며 오차 보증이 아닙니다. 이미지 방향을 센서 좌표로 역변환하고 카메라 내부 파라미터로 depth(Z)를 역투영한 뒤 AR 월드 변환을 적용합니다. 거리 자체를 Z-depth로 대체하지 않습니다.

## 1인 이동 PoC · AirPods 통합 (2026-10-01)

첫 탭 `1인 이동 PoC`에서 실행합니다. 운영자는 스캔 후에도 같은 iPhone으로 P를 계속 촬영하고, P는 그 iPhone에 연결된 AirPods를 착용합니다. 실측에는 sceneDepth와 사람 분할을 함께 지원하는 LiDAR 기기, 음향에는 머리 방향을 제공하는 AirPods와 동작 및 피트니스 권한이 필요합니다.

### 현장 순서

1. `무대 스캔하고 P 추적하기` → 바닥·원점·앞 방향·경계를 입력합니다.
2. 경계를 닫으면 같은 ARSession에서 P를 추적합니다. P 한 명만 화면에 담고 `#번호를 P로 선택`합니다. 위치는 몸통의 바닥 투영 추정값입니다.
3. 평면도 내부를 터치해 D를 지정합니다.
4. `소리 준비`를 누릅니다. AirPods를 연결하고 권한을 허용합니다. 권한 창 때문에 앱이 비활성화되어 정지한 경우 `소리 준비`를 다시 누릅니다.
5. P가 한 방향을 보고 서게 한 뒤 `P가 보는 방향 지정` 모드에서 그 방향의 점을 지도에 찍습니다. 그 순간의 AirPods yaw를 무대 방향에 맞춥니다. 폰을 바라볼 필요는 없습니다.
6. `안내 시작`을 누릅니다. 목표 D에 고정된 것처럼 들리는 0.25초 잡음이 0.6초 간격으로 반복됩니다. 머리 회전과 P의 위치 변화를 모두 반영합니다.
7. **D에 가까워지면 커지고, D에서 멀어지면 작아집니다.** 도착 반경 0.3m에서는 안내음을 멈추고 상승하는 세 음과 “도착” 음성을 재생합니다. 도착 후 멀어져도 자동으로 안내를 재개하지 않습니다.

지도 화살표와 방향 숫자는 실측 모드에서는 **AirPods 머리 방향** 기준입니다. 몸통·발·이동 방향과 같다는 뜻은 아닙니다. 정지한 채 고개를 돌려 목표 방향을 탐색할 수 있습니다. 센서 없는 조작 예제에서는 기존 이동 방향 추정을 사용하고 실제 소리는 내지 않습니다.

### 음량 규칙

`BeaconMath.distanceGain(d) = 0.6 × 0.5 / max(0.5, d)`를 사용합니다. 예: 0.5m=60%, 1m=30%, 2m=15%, 4m=7.5%, 8m=3.75%. 8m보다 멀어져도 계속 감소하며, 0.5m 이내는 최대값으로 제한합니다. 도착·일시 정지·유효기간 만료에서는 0입니다.

이 값은 앱의 선형 진폭 계수이며 시스템 볼륨, 체감 음량 비율 또는 실제 음압이 아닙니다. 거리 노이즈로 갑자기 변하지 않도록 약 0.15초 시정수로 증가·감소를 모두 평활화합니다. 음향 엔진의 `referenceDistance`를 1,000m로 두어 앱이 허용하는 무대 좌표 범위(±200m) 전체를 추가 감쇠가 없는 구간에 포함합니다. `rolloffFactor`는 Apple이 요구하는 양수(1)를 사용합니다. 이중 감쇠 없이 앱의 음량 계수만 반영합니다. 공간음향 위치는 실제 P·D 좌표를 그대로 사용합니다.

설정 근거: [Apple referenceDistance](https://developer.apple.com/documentation/avfaudio/avaudioenvironmentdistanceattenuationparameters/referencedistance), [rolloffFactor](https://developer.apple.com/documentation/avfaudio/avaudioenvironmentdistanceattenuationparameters/rollofffactor).

### 중단과 재시작

- **1인 PoC에서는 P를 한 번 선택하면 감지 누락·내부 ID 변경·부분 가림으로 선택을 지우지 않습니다.** 화면 밖에서도 선택을 유지해 같은 한 사람의 재등장을 기다립니다. `P 선택 해제` 또는 세션 초기화로만 선택을 해제합니다.
- P가 영상에서 확인되지만 한두 프레임의 깊이 측정이 누락되면 마지막 실측 위치를 원래 측정 시각 기준 최대 0.5초까지만 사용합니다. 새 측정처럼 시간을 갱신하지 않습니다. 영상에서도 P가 사라지거나 실측 위치가 0.5초를 초과하면 위치 표시와 음향을 중지합니다. 안내 중이었다면 새 위치와 유효한 AirPods 방향이 돌아왔을 때 재선택 없이 재개합니다. 사용자가 누른 정지, AirPods 보정 상실, 무대 경계 차단은 자동 재개하지 않습니다.
- AirPods 머리 방향 0.5초 초과 지연: 즉시 무음으로 전환하되, 마지막 샘플 기준 최대 2초까지 보정과 안내 의도를 유지합니다. 이 시간 안에 새 방향·위치가 돌아오면 재개합니다. 2초를 초과하거나 출력/엔진이 바뀌면 보정을 해제하고 방향을 다시 지정해야 합니다. 보정 유지 시간에도 오래된 방향으로 소리를 재생하지 않습니다.
- 정상적인 출력 설정 알림은 현재 이어폰과 엔진이 유지되면 계속 사용합니다. 이어폰은 연결되어 있고 엔진만 정지했으면 안내를 음소거하고 250ms 뒤 엔진 복구를 최대 3회 시도합니다(2초 안정 동작 후 횟수 초기화). 복구 후 초기 방향을 다시 지정해야 합니다. 실제 이어폰 출력 상실·전화 등 오디오 중단에서는 전체 음향을 종료하며, 폰 스피커로는 재생하지 않습니다.
- 한쪽 AirPod만 벗는 것은 출력 경로 변경으로 검출되지 않을 수 있습니다. 양쪽 착용 여부를 보장하는 기능은 아닙니다.
- 일시 비활성(권한 팝업 등): 안내와 방향 보정을 중지하되 센서 수신은 유지합니다. 백그라운드·화면 이탈: 음향 종료. 백그라운드나 AR 세션 중단: 재스캔 필요.

머리 방향 지연 대응: 기존에는 0.5초 지연 한 번으로 보정을 삭제해 재지정을 반복하게 했습니다. 이제 짧은 지연에서는 무음 상태로 보정을 유지합니다. Core Motion 콜백은 별도 직렬 큐에서 수신하고, 실제 센서 시각·콜백 수신 시각·메인 화면 반영 시각을 분리합니다. 진단의 `앱 반영 지연`과 지연/복구 이벤트로 센서 수신 지연과 앱 처리 지연을 구분할 수 있습니다. 센서 시각을 수신 시각으로 덮어써 오래된 데이터를 유효하게 만드는 처리는 하지 않습니다. 관련 핵심 검사 66개와 iOS 빌드가 통과했으며, 실제 지연 원인 확정 및 AirPods 동작 확인에는 실기기 진단이 필요합니다.

치직 소리가 잘리는 현상 대응: 정상 패턴은 0.25초 재생 + 0.35초 휴식입니다. 이전에는 P가 계속 보여도 깊이 측정 한 프레임 실패만으로 `player.stop()`을 호출했습니다. 이제 위의 0.5초 위치 유효기간 안에서 짧은 누락을 처리하고, 진단에 `안내 무음: ...`과 `안내 재생 가능`을 기록합니다. 관련 핵심 검사 68개가 통과했습니다. 실제 기기의 끊김 원인은 무음 사유와 머리 센서/출력 이벤트를 함께 확인해야 하며 Bluetooth 전송 오류로 단정하지 않습니다.

Apple 참고: [출력 변경 사유](https://developer.apple.com/documentation/avfaudio/avaudiosession/routechangereason), [설정 변경 시 엔진 정지](https://developer.apple.com/documentation/avfaudio/avaudioengineconfigurationchangenotification).

수정 후 안내 핵심 검사 50개와 iOS 서명 제외 빌드가 통과했습니다. 보고된 실기기의 이벤트 로그는 아직 확보하지 못했으므로 정상 설정 변경이 실제로 발생한 순서와 재발 여부는 수정본에서 확인해야 합니다.


### 1인 P 선택 유지·부분 영상 추적

`SinglePersonVisionTracker.swift`를 1인 PoC에만 사용합니다. 기존 `사람 감지` 탭의 여러 사람 실험 코드는 별도로 유지됩니다.

- 최초 P 후보는 목·골반 신뢰도 >0.45 및 high confidence 깊이를 요구합니다.
- P 선택 이후에는 신뢰도 >0.2의 목·골반 중점, 양쪽 어깨/골반 중점, 골반 또는 목 한 점을 차례로 사용합니다. 깊이는 medium 이상, 7×7 주변 패치로 완화합니다. 최소 5개 표본·0.2~6m 깊이·중앙절대편차 ≤0.12m 검사는 유지합니다. 상체·골반 등 사용하는 부위가 바뀌면 추정 위치가 흔들릴 수 있으며 정밀도는 실측해야 합니다.
- 관절이 부족하면 `VNTrackObjectRequest`로 이전 영상 영역을 추적하고 사람 마스크가 겹치는지 확인합니다. 상체 사각형 검출도 재획득에 사용합니다. 영상 회전 시 영상 추적기를 다시 초기화하지만 P 선택은 유지합니다.
- 팔·다리만 보이는 경우에는 영상 추적과 P 선택을 유지할 수 있지만, 그 부위를 몸통 중심의 현재 위치로 간주하지 않습니다. 몸통 기준점과 깊이를 다시 얻을 때까지 음향은 무음입니다.
- 오퍼레이터의 P 선택과 감지기의 프레임별 ID를 분리했습니다. **화면에 들어오는 사람은 같은 P 한 명이라는 실험 조건**을 전제로 하므로 다른 사람이 대신 들어와도 구별하지 않습니다. 얼굴·개인 신원 인식이 아닙니다.
- 어떤 크기의 신체 조각이라도 검출된다는 보장은 없습니다. 화면에 보이더라도 너무 작거나 가려져 영상 추적이 실패할 수 있습니다. 이때도 P 선택 자체를 삭제하지 않습니다.

조작 예제의 `P 영상 보임` / `P 위치 측정 가능`을 각각 끄고 켜서 선택 유지·무음 대기·복구를 시험할 수 있습니다. 추적 설명에 영상 유지, 몸통/깊이 측정 대기, 처리 지연을 구분해 표시합니다.

관련 핵심 검사: 안내 상태 55개 + 사람 추적/부분 몸통 기준 33개 통과. 실제 부분 가림·팔만 보이는 영상·복귀 시 오차는 실기기 미검증입니다.

### 검토만 한 대안: AirPods 좌우 위치로 P 위치·방향 계산

공개 `CMHeadphoneMotionManager`/`CMDeviceMotion` API는 자세·회전·가속도 등을 전달하며, 좌우 이어버드 각각의 무대상 XYZ 좌표를 제공하지 않습니다. `sensorLocation`의 left/right는 어느 쪽 센서의 데이터인지 나타내는 구분값이지 위치 좌표가 아닙니다. 따라서 이 API만으로 좌우 이어버드의 중점을 구해 무대 위치를 얻는 방식은 구현할 수 없습니다.

카메라로 이어버드 두 개를 검출하는 별도 방식은 검토상 가능하지만, 작은 대상·고개 회전·머리/귀에 의한 가림 때문에 몸통 추적보다 안정적일 것이라고 보기 어렵습니다. 이 대안은 코드에 적용하지 않았습니다. 현재는 카메라·LiDAR로 P 위치를 얻고 AirPods 자세로 머리 방향을 얻습니다.

근거: [CMHeadphoneMotionManager](https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager), [sensorLocation](https://developer.apple.com/documentation/coremotion/cmdevicemotion/sensorlocation-swift.enum), [Vision 객체 추적](https://developer.apple.com/documentation/vision/vntrackobjectrequest).
