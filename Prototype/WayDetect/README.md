# WayDetect POC 2

실내에서 배 앞에 세로로 고정한 iPhone으로 **시계 방향 + 걸음 + 정지 후 자동 도착**을 시험하는 SwiftUI 앱입니다. 화면은 몸 정면을 향합니다. 지도·카메라·위치 권한을 사용하지 않습니다.

## 실행

1. `WayDetect.xcodeproj`를 Xcode에서 엽니다.
2. Signing & Capabilities에서 자신의 Team과 iPhone을 선택합니다.
3. Run 후 동작 및 피트니스 권한을 허용합니다.
4. 경로에서 각 스팟의 **몇 시 방향 / 몇 걸음**을 입력합니다.
5. 측정 → 출발점 확인 → 센서 켜기 → 약 1초 정지 → **12시 설정**.
6. 목표 방향으로 몸을 돌리고 **출발**을 누릅니다.
7. 목표 추정 걸음에서 ‘멈추세요’를 안내합니다. **목표 방향을 향해 1.5초 연속 정지**하면 자동 도착으로 처리하고, 현재 정면을 새 12시로 설정해 다음 스팟을 안내합니다. 다음 목표 방향 12° 이내를 새 센서 표본에서 0.6초 유지하면 버튼 없이 자동 출발합니다. 이때 다시 정지할 필요는 없으며 보행 중 흔들림만으로 출발을 막지 않습니다.
8. 마지막 스팟은 같은 정지 조건에서 자동 완료합니다. 완료 또는 수동 종료 후 **기록 저장 / 저장 안 함**을 선택합니다.

자동 도착은 **목표 추정 걸음 이후 목표 방향에서 정지**를 기준으로 한 POC 규칙이며, 실제 위치를 확인하는 기능은 아닙니다. 목표 전에 잠깐 멈추면 도착 처리하지 않습니다. 목표 도달 후에도 목표 방향에서 12°를 넘겨 벗어나거나, 움직임·회전·새 추정 걸음·센서 수신 간격 이상이 있으면 정지 시간을 다시 셉니다. 새 센서 표본으로 연속 정지를 확인해야 하며 시간만 지나서는 완료하지 않습니다.

목표 방향은 바로 이전 스팟에서 설정한 정면을 기준으로 합니다. 예: 첫 스팟 3시 → 정지 당시 정면을 새 12시 → 다음 스팟 3시라면 다시 오른쪽으로 회전합니다. 수동 도착 확인 버튼은 사용하지 않습니다.

## 걸음 수의 의미

- **이번 이동 · 추정 걸음**: 허리의 수직 가속도를 50 Hz로 처리한 자체 계산값. 수동 출발은 버튼을 누른 시점부터, 다음 구간 자동 출발은 확인된 0.6초 방향 정렬의 시작 시점부터 걸음을 반영합니다. 정렬 이전에 몸을 돌리며 감지한 후보는 구간에 넣지 않습니다. 독립 센서 큐에서 처리하므로 화면·파일 저장이 샘플 처리를 막지 않습니다.
- **추정 세션 누적**: 설정·회전·정지 중 감지한 움직임도 포함한 전체 추정값.
- **iOS 세션 누적**: CMPedometer의 세션 시작 시각 기준 누적값. 실시간 콜백과 2초 간격 조회를 병행하며 같은 누적값을 더하지 않습니다. 이동 구간 전환 시 수신을 끊지 않습니다.
- 추정과 iOS 값을 **합산하거나 자동으로 바꾸지 않습니다**. 출발·회전·정지 구간의 포함 범위와 반영 지연도 다르므로 두 값의 차이는 정확도의 정답이 아닙니다.
- 추정기는 위/아래 가속도 한 주기와 보행 간격을 확인합니다. **첫 두 주기를 함께 인정하므로 처음에는 0에서 2로 표시될 수 있습니다.** 첫걸음이 바로 표시되는 방식은 아니며, 별도의 5초 대기시간은 없습니다. 첫 후보가 출발 전이었다면 구간에는 출발 후 후보만 반영합니다.
- 작은 보폭·아주 느린 보행·허리 흔들림·휴대폰 흔들림에서 누락/과대 계산될 수 있습니다. 낮은 가속도에서는 감지 문턱에 도달하지 못할 수 있고, 빠른 회전·잘못된 자세·수신 공백은 검출기의 보행 주기 확인을 초기화합니다. 실제 보행 검증 전입니다.

## 방향과 복구

화면의 법선(+Z)을 중력 기준 수평면에 투영해 몸 정면을 구합니다. 상대 회전 `.xArbitraryZVertical`을 사용하고 자기장 보정은 사용하지 않습니다. 최초 정면은 최근 1초의 수신·방향·흔들림을 검사한 뒤 설정합니다.

측정 중에는 상단의 **방향 재설정**을 언제든 누를 수 있습니다. 원하는 정면을 본 채 1초 연속 정지하면 새 기준을 설정하며, 현 구간의 걸음 수와 목표 걸음은 유지합니다. 이미 출발한 구간은 현재 정면을 이동 목표인 12시로 바꿉니다. 아직 출발하지 않은 구간은 새 정면에서 경로의 시계 방향을 적용합니다. 남은 이동은 **출발 또는 계속 걷기** 버튼으로 시작하며 재설정만으로 보행을 재개하지 않습니다. 목표 걸음을 이미 채웠다면 재설정 후 자동 도착을 위한 1.5초 정지를 다시 기다립니다.

이동 중 방향이 18° 이상 벗어난 상태가 1초 유지되면 ‘11시로.’ 같은 보정 안내를 냅니다. 첫 보정은 출발 안내의 대기시간과 무관하게 나가며, 이탈이 계속되면 3초 간격으로 반복합니다. 목표 방향에 돌아오면 ‘방향 맞음.’을 한 번 안내합니다. 목표 걸음을 채웠어도 방향이 틀리면 보정을 계속하고, 목표 방향을 맞추기 전에는 자동 도착하지 않습니다. 다음 스팟의 방향 맞추기에서도 안내를 반복하며 방향이 안정되면 자동 출발합니다.

큰 이탈, 방향 수신 끊김, 잘못된 착용, 오디오 중단은 정지합니다. 큰 이탈로 일시정지해도 방향 센서가 유효하면 짧은 보정 안내를 계속합니다. 정지 중에도 센서는 계속 수신합니다. 같은 방향 기준이 유효하면 위치와 남은 걸음을 확인한 뒤 재개합니다. 일시정지 또는 수동 방향 재설정 후에는 자동 출발하지 않습니다.

앱 전환/잠금 후에는 기존 좌표계를 폐기합니다. 같은 **방향 재설정** 버튼으로 기준을 다시 잡을 수 있으며 이전 스팟으로 돌아갈 필요는 없습니다. 기준 설정 후 2분을 넘긴 이동도 재설정이 필요합니다. **점진적인 자이로 오차와 폰이 몸에서 돌아간 것을 센서만으로 확정할 수는 없습니다.** 재설정은 현재 위치를 복구하지 않으므로 실제 위치·정면은 사용자/동행자가 확인합니다.

음성/VoiceOver는 ‘3시. 10걸음.’, ‘조금 오른쪽.’, ‘멈추세요.’처럼 짧게 안내하며 각도를 읽지 않습니다. 새 안내는 이전 안내 뒤로 쌓지 않고, ‘다시 안내’와 정지 안내는 같은 말이라도 재생합니다. 진동은 출발·방향·정지·완료·주의를 구분하며 좌우를 진동으로 부호화하지 않습니다.

## 결과와 보존

걸음 비교, 시계 방향, 수직 가속도 그래프를 제공합니다. 스팟 필터, 가로 스크롤, 표시 시간 확대/축소, 시점 선택, iOS 곡선 표시, 기준선 표시, CSV/JSON 공유가 있습니다.

POC v2 데이터는 앱 컨테이너의 `Library/Application Support/WayDetect/POC-v2`에 저장합니다. 기존 v1 경로는 이동/회전 순서를 스팟으로 변환해 읽습니다. v1 기록 파일은 삭제하거나 덮어쓰지 않으며 v2 대시보드에는 섞지 않습니다. 종료 후 선택 전에는 복구용 임시 기록만 보관합니다. ‘저장 안 함’은 그 임시 기록을 삭제합니다.

## 코드 구조

- `WayDetectCore`: 순수 상태 머신, 시계 방향/자세 수학, 안정 구간, 가속도 걸음 추정.
- `MotionService`: 센서 수신과 동시 접근을 처리. 경로 상태에 의존하지 않음.
- `SessionController`: 앱 생명주기, 안내, 결과 저장 선택 연결.
- SwiftUI 화면: 경로 / 측정 / 기록 / 설정. 실험용 자기장·장착 방향·다수 임계값 설정은 제거.

실제 시각장애인 보행 정확도와 안전성을 검증한 제품이 아닙니다. 동행자가 확인한 실내 경로에서 [실기기 시험](Documentation/DEVICE_TEST.md)을 먼저 진행합니다. 자동화 시험은 [검증 기록](Documentation/VALIDATION.md)을 참조하세요.
