# PoC4 Scan Lab — 1단계

이슈 [#6](https://github.com/DeveloperAcademy-POSTECH/2026-C6-A13-Hear-I-am/issues/6) · 브랜치 `PoC4-1`

아이폰 한 대로 무대를 메시 스캔하고 저장한 공간을 재실행 후 복원하며, 배에 착용한 카메라의 위치·방향을 기록하는 실험 앱이다. 기존 PoC 앱과 별도 프로젝트다. 도면 A, K1~K4 정합, 장애물 종류 등록, 경로 안내, YOLO 및 실시간 미등록 물체 감지는 아직 구현하지 않는다.

## 실행

- LiDAR와 ARKit scene reconstruction을 지원하는 iPhone, iOS 17 이상이 필요하다.
- `PoC4.xcodeproj`를 Xcode로 열고 PoC4 타깃의 Signing Team을 본인 팀으로 지정해 실제 기기에 실행한다. 카메라 권한을 허용한다.
- 프로젝트 변경 시 이 디렉터리에서 `xcodegen generate`로 `project.yml`을 반영한다. 일반 실행에는 XcodeGen이 필요 없다.
- 코어 검사: 저장소 루트에서 `sh PoC4/scripts/test-core.sh`.
- 시뮬레이터는 미지원 안내와 UI 실행 확인용이다. 메시·복원·착용 성능은 실제 기기에서 검사한다.

## 스캔 → 저장 → 앱 재실행 → 복원 → 착용

1. 바닥에 **O(원점), F(객석 방향), C(독립 확인점)**를 표시한다. O→F는 객석 정면을 향하도록 하고, 세 점은 서로 0.5m 이상 떨어진 같은 바닥에 둔다. O–F를 충분히 멀리 두고 C는 다른 위치에 두면 검증하기 좋다. 이들은 1단계 실험 기준이며 이후 도면용 K1~K4와 다르다.
2. **새 스캔 시작** 후 무대 바닥, 박스·계단의 표면, 주변의 안정적인 시각 특징을 천천히 촬영한다. 화면의 초록 메시가 수집 결과다. 메시만으로 박스/계단의 종류를 판별하지 않는다.
3. 카메라 화면 중심 십자선을 실제 바닥 표식 중심에 맞춰 O → F → C를 선택한다. 이미 인식된 수평면에만 선택 가능하다. 상자 윗면이 아니라 무대 바닥인지 사람이 확인한다.
4. 추적이 normal이고 공간 지도가 mapped이며 기준 앵커와 메시가 확보되면 이름을 입력하고 **메시와 공간 지도 저장**한다. 성공 시 세션이 정지한다. 저장 실패 시 새 스캔을 진행한다.
5. 앱을 완전히 종료하고 다시 실행한다. 저장 공간을 선택하고, 원래 스캔했던 특징과 표식을 카메라에 보여준다. 저장 메시(주황)는 복원 후보가 확보되면 표시된다. 이것만으로 복원 정확도를 통과한 것은 아니다.
6. **실제 바닥 C**에 십자선을 맞추고 **실제 C 다시 선택 · 오차 검증**을 누른다. 화면 가상 C를 따라 찍지 않는다. normal 추적과 저장 기준 앵커가 1초 이상 연속 유지되고, 선택한 C와 저장 C의 3D 차이가 0.15m 이내이면 착용 실험을 허용한다.
7. **8초 후 착용 기록 시작**을 누르고 배 앞에 폰을 세로 고정한다. 후면 카메라는 앞쪽, 화면은 몸 쪽을 향한다. 렌즈를 가리지 않고 밴드 안에서 폰이 돌아가지 않게 한다. 카운트다운 중 추적이 깨지면 C를 다시 검증한다.
8. 실측 위치와 회전 각도를 기록하며 움직인다. 구간 종료 후 필요하면 폰을 분리해 메모를 입력한다. **측정 종료 · 로그 저장** 후 JSONL을 공유한다. 파일 앱에서도 앱의 Scans/Trials 폴더에 접근할 수 있다.

처음 카메라 권한 창이나 앱 비활성화로 세션이 중단되면 새 스캔/저장 공간 선택을 다시 누른다. 공간 복원 자체가 60초 이상 안정화되지 않으면 세션을 종료한다. 기준점 검증 대기 시간은 별개다.

## 좌표·품질의 의미

- 단위 m. 무대 좌표 +X는 도면 오른쪽, +Y는 무대 뒤, Z는 O 바닥에서의 높이. 객석을 향할 때 몸의 오른쪽은 -X다.
- 방향은 후면 카메라 광학 정면을 바닥에 투영한 각도다. 객석 0°, 몸의 오른쪽 회전 +90°, 왼쪽 -90°. 폰 고정 축이 몸 정면과 같다는 전제가 있다. 옆걸음·뒷걸음에서 이동 방향으로 바꾸지 않는다.
- 좌표는 **카메라 위치**다. 발 위치나 신체 중심의 실측값이 아니며 장착 오프셋을 자동 보정하지 않는다.
- 추적 제한/앵커 누락/0.5초 이상 표본 단절 시 검증 상태를 폐기한다. 정상으로 돌아와도 C를 다시 검증해야 한다. 앱 비활성화·AR 오류는 세션을 끝내고 다시 불러오게 한다.
- 착용 중 카메라가 너무 위/아래를 향해 수평 방향을 구할 수 없으면 착용을 중단한다.
- 0.15m는 실험 게이트 값으로 정확도 보증이 아니다. C 한 점은 전체 무대의 회전·축척·드리프트를 증명하지 않는다. 아래 실측 절차로 O/F와 여러 지점도 평가해야 한다.

## 저장 형식

`Documents/Scans/<UUID>/`에 아래 세 파일을 새 ID로 저장한다. 임시 디렉터리 작성 완료 후 이동하며 기존 ID를 덮어쓰지 않는다.

- `worldmap.bin`: ARWorldMap 보안 아카이브. 공간 재로컬라이제이션에 사용한다.
- `mesh.json`: 메시 앵커별 UUID, 로컬 정점·삼각형 인덱스·월드 변환. 시각화용 형상이다.
- `manifest.json`: 버전, 이름, 날짜, O/F/C, 메시 개수, 기기/앱 정보와 두 데이터 파일의 SHA-256.

로드 시 버전·유한 좌표·삼각형 인덱스·개수·해시를 검사한다. ARWorldMap의 기준 앵커도 검사한다. 형상 파일만으로 공간 복원이 되는 것은 아니다. 스캔 범위·기기 메모리에 따른 부담이 있어 총 정점 80만 초과 시 실험을 중단한다.

## 로그

`Documents/Trials/trial-<UUID>.jsonl`. 첫 줄은 scanID, sessionID, OS, 앱 버전, 허용값과 좌표 설명을 담은 header다. 다음 줄은 다음 필드를 가진다.

| 필드 | 의미 |
| --- | --- |
| sequence | 기록 큐에 넣은 순서 |
| wallTime / uptime | ISO 날짜 / 부팅 후 시간. pose는 카메라 프레임 timestamp, 다른 이벤트는 이벤트 처리 시간 |
| event / detail | pose, tracking, reference_O/F/C, checkpoint, wear_start/stop/invalidated, manual_note, session_start/end/interrupted 등 |
| position / heading | 관측 위치 / 도 단위 방향. 관측 불가하면 생략 |
| coordinateSpace | reference와 checkpoint는 ar-world(x,y,z), pose는 stage(X,Y,높이) |
| tracking / mapping | ARKit 추적 상태 / 지도 상태 |
| verified | 해당 시점 품질 게이트 및 C 검증 통과 여부 |
| errorMeters | checkpoint 재선택 오차 |

위치는 최대 약 20Hz로 세션 시작부터 기록한다. `detail=wearing`인 pose가 착용 구간이다. 미검증 관측도 분석을 위해 남기므로 **verified=false를 유효 위치로 해석하지 않는다**. 파일 쓰기 오류는 측정을 종료한다. 정상 종료 시 큐를 비우고 디스크에 동기화한다. 강제 종료/전원 중단 시 마지막 줄이나 마지막 일부 기록은 손실될 수 있다.

## 실제 기기 검증 — 아직 미실시

동일 스캔으로 적어도 3회 반복하고 기기 모델·OS·조명·스캔 시간·이동 거리·착용 높이를 메모한다.

- [ ] 바닥과 박스/계단 1~2개 메시가 저장 후 다시 표시된다.
- [ ] 앱 강제 종료 → 재실행 → 같은 공간 선택 → 복원 시간·성공/실패 기록.
- [ ] normal만으로 위치를 사용하지 않고, C 검증 전에는 착용 시작이 비활성이다.
- [ ] C를 의도적으로 틀리게 선택하면 실패하고, 실제 C를 선택하면 오차가 기록된다.
- [ ] 줄자로 정한 O/F 및 별도 3곳 이상에서 카메라 수평 투영 위치 오차를 실측한다. 각 지점 측정값·평균·최대 오차를 남긴다.
- [ ] 객석/오른쪽/뒤/왼쪽 0/90/180/-90° 정지 자세의 방향 오차를 측정한다.
- [ ] 배 착용 전후, 직진/옆걸음/뒷걸음/회전과 원점 복귀 후 오차를 비교한다.
- [ ] 의상 가림·빠른 회전·저조도·앱 백그라운드에서 검증 해제와 재검증 흐름을 확인한다.
- [ ] 장시간 착용 시 기록 주기·발열·배터리·드리프트를 측정한다.
- [ ] 공유한 JSONL에서 구간·메모·오차·무효 상태가 확인된다.

첫 실험은 동행 검증자가 있는 통제된 공간에서 수행한다. 이 앱에는 충돌/낙상 방지 안내가 구현되어 있지 않다.

## 스캔 공간 3D 보기

메시가 수집되면 카메라 아래 **스캔 공간 3D 보기**를 누른다. 독립 가상 카메라로 한 손가락 회전, 두 손가락 이동, 핀치 확대/축소가 가능하다. **전체 보기**는 전체 메시를 다시 화면에 맞춘다. 면 렌더링과 와이어프레임을 전환할 수 있다. 저장 직후 또는 저장 공간을 불러온 뒤에도 같은 버튼으로 형상을 확인한다.

미리보기를 여는 동안 AR 세션과 스캔은 유지된다. 메시 변경분은 약 0.5초 간격으로 반영하며 사용자가 조절한 시점은 유지한다. 창을 닫으면 추가 렌더링 노드를 해제한다. 스캔되지 않은 면은 표시할 수 없으며 사진 질감이나 자동 물체 분류는 제공하지 않는다. 3D 표시가 가능하더라도 공간 복원·C 검증은 별도로 통과해야 한다.

실기기 추가 검사: 스캔 중 미리보기에서 새 표면이 추가되는지, 회전/확대/전체 보기, 면·선 전환, 닫은 뒤 기준점 선택, 저장/재실행 후 형상 일치와 발열·프레임 저하를 확인한다.
