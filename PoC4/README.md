# PoC4-2 현장 스캔 기반 순차 경로 안내

이슈 [#8](https://github.com/DeveloperAcademy-POSTECH/2026-C6-A13-Hear-I-am/issues/8) · 브랜치 `PoC4-2`

LiDAR 지원 iPhone 한 대로 무대를 스캔하고, 같은 기기에서 현장 경로를 작성한 뒤 배에 착용하여 현재 몸 정면 기준 8방위와 목적지까지의 수평 거리로 안내하는 **실험 앱**이다. 기존 PoC4-1의 메시 스캔, ARWorldMap 복원, 독립 확인점 검증, 착용 로그와 독립 3D 보기를 재사용한다. 실기기 정확도·성능과 에어팟 명령 수신 여부는 아직 검증되지 않았다.

## 빌드와 실행

- LiDAR 및 ARKit scene reconstruction을 지원하는 iPhone, iOS 17 이상이 필요하다. `PoC4.xcodeproj`를 열고 Signing Team을 설정한 뒤 카메라 권한을 허용한다.
- 저장소 루트에서 `sh PoC4/scripts/test-core.sh`로 코어 XCTest를 실행한다. 프로젝트 설정을 바꾸면 `PoC4/`에서 `xcodegen generate`를 실행한다.
- Simulator는 UI·빌드 확인용이다. 카메라 메시, 공간 복원, 위치 정확도, 에어팟 명령, 오디오 경로는 실제 기기에서 확인한다.
- 스캔과 안내 내내 앱을 전경에 두고 화면 잠금을 해제한다. 화면 잠금이나 백그라운드 AR 추적은 전제하지 않는다.

## 사용 순서

1. 무대 바닥과 박스·계단 등의 표면 및 주변 고정된 시각 특징을 천천히 스캔한다. 십자선은 이미 관측된 **수평 바닥면**에만 찍힌다. 메시 표시는 장애물 등록이나 정확도 검증을 뜻하지 않는다.
2. 객석에서 바라본 **앞왼쪽 → 앞오른쪽 → 뒤오른쪽 → 뒤왼쪽**을 차례로 선택한다. 같은 버튼을 다시 누르면 해당 점을 수정한다. 네 점의 평면 높이, 순서·자기 교차, 직각, 대변 길이·잔차를 검사한다. 앞 변과 안쪽 방향으로 직사각형 E 및 객석을 향한 무대 정면이 정해진다. 오류가 크면 점을 다시 찍는다.
3. **스캔 공간·E·경로 3D 보기**에서 메시와 E 표시를 회전·확대해 확인한다. 수집되지 않은 면은 표시되지 않는다.
4. E의 바닥에 **p0**를 따로 찍고 목적지 **p1~p5**를 순서대로 최대 다섯 개 찍는다. 목록에서 각 점을 다시 찍거나 삭제할 수 있다. p0 포함 최대 여섯 점이며 최소 p0→p1이 필요하다.
5. 물체의 바닥 점유 영역을 둘러싸는 꼭짓점 3~8개를 찍고 계단/박스/기타 종류와 이름을 입력해 등록한다. 꼭짓점별 수정·삭제와 등록 물체의 수정·삭제가 가능하다. 종류와 통과 정책은 저장 형식에서 별도이며, 이 앱에서 등록한 모든 물체는 **통과 금지**다. 계단 위로 이동하는 안내는 없다.
6. 경로의 모든 점·선분에 무대 경계 여유와 등록 장애물 여유를 적용한다. 충돌 메시가 있으면 점이나 물체 영역을 수정한다. 자동 우회는 없다. 경계·장애물 여유는 저장 전 실험 설정에서 조정한다.
7. E의 네 꼭짓점과 **별개인 실제 바닥 확인점 C**를 표시해 선택한 뒤 지도·메시·E·경로를 저장한다. 저장 성공 시 AR 세션이 멈춘다.
8. 앱을 완전히 종료하고 다시 열어 저장 공간을 선택한다. 원래의 무대 특징을 천천히 비춘 후 실제 C를 다시 선택해 오차를 확인한다. 화면의 가상 C를 따라 찍지 않는다. 추적 normal과 저장 앵커가 1초 이상 안정되고 C 오차가 0.15m 이내여야 한다.
9. **8초 착용 준비 카운트다운**을 누르고 폰을 배 앞에 세로로 단단히 고정한다. 후면 카메라는 몸 앞쪽, 화면은 몸 쪽이다. 렌즈를 가리지 않고 폰이 밴드 안에서 돌아가지 않게 한다.
10. p0에 위치해 무대 정면을 향한다. C 검증, 추적 품질, p0 근접, 정면 오차, 경로 검사가 모두 유효할 때 화면 **안내 시작**을 누른다. 에어팟 재생 명령은 실기기에서 수신 여부를 시험할 수 있지만, 동작을 보장하지 않는다.
11. 안내는 현재 몸 정면 기준 **앞 / 오른쪽 앞 / 오른쪽 / 오른쪽 뒤 / 뒤 / 왼쪽 뒤 / 왼쪽 / 왼쪽 앞**과 현재 목적지까지의 수평 거리다. 예: “오른쪽 앞, 2.0미터.” 옆걸음·뒷걸음에서 이동 벡터를 몸 방향으로 간주하지 않는다. 8방위 경계에 6° 히스테리시스를 적용하고 음성 반복은 3초 이상 간격을 둔다.
12. 현재 목표 반경에 머문 시간이 기준을 넘으면 그 목표에 도착한 것으로 보고 **바로 다음 번호**로 진행한다. 경로가 교차하거나 다른 목적지에 먼저 가까워져도 건너뛰지 않는다. 마지막 목적지에서 종료한다.

## 실험 설정 기본값

| 설정 | 초기값 | 이유와 검증 필요성 |
| --- | ---: | --- |
| p0 시작 반경 | 0.45m | 착용 카메라와 바닥 표식의 차이를 허용하는 첫 실험값. 실제 폰·발 오프셋은 실측 필요 |
| 무대 정면 허용 오차 | ±20° | 시작 자세가 대략 정면인지 제한하는 첫 실험값. 거치 방향 오차 실측 필요 |
| 도착 반경 | 0.35m | 정지 시 AR 위치 흔들림을 견디기 위한 첫 실험값. 잘못된 도착률 측정 필요 |
| 도착 체류 시간 | 0.8초 | 단발 위치 튐으로 인한 진행을 줄이기 위한 첫 실험값 |
| 무대 경계 여유 | 0.30m | 경계선과 경로 사이 초기 여유. 실제 안전 여유는 별도 결정 필요 |
| 장애물 여유 | 0.35m | 수동 등록 오차와 몸 폭에 대한 초기 여유. 장애물 실측 필요 |
| 안내 반복 / 방위 히스테리시스 | 3초 / 6° | 프레임마다 말하지 않고 방위 경계 반복 전환을 제한 |
| 추적 표본 만료 / C 오차 | 0.5초 / 0.15m | 기존 PoC4-1 게이트를 유지. 정확도 보증값이 아님 |

설정은 스캔·경로 저장 전에 조정하며 저장된 공간에 함께 기록된다. 저장 후 안내 중에는 설정을 수정하지 않는다. 현재 위치는 **카메라 위치의 무대 바닥 수평 투영**이며 발 위치나 몸 중심 실측값이 아니다. 좌표 단위는 m, +X는 객석에서 보는 무대 오른쪽, +Y는 무대 뒤쪽, Z는 바닥 위 높이이다. 몸 정면 각도 0°는 객석 방향이며 양수는 착용자 오른쪽 회전이다.

## 에어팟 재생/일시정지 실험과 중단

앱은 `MPRemoteCommandCenter`의 play, pause, toggle 명령을 받아 시작·일시정지·재개를 시도한다. 오디오 세션을 활성화하고 Now Playing 제목·재생 상태를 설정한다. 일반 에어팟 터치를 직접 읽는 구현이 아니다. 모델·iOS·현재 오디오 라우트에 따라 명령이 전달되지 않을 수 있으므로 화면 버튼을 항상 대안으로 둔다. 준비 조건을 충족하지 못한 play 명령은 안내를 시작하지 않는다.

추적 유실·오래된 프레임·무대 이탈·앱 비활성화·AR 세션 오류·오디오 중단은 안내를 일시정지하거나 세션을 중단한다. 추적 복구만으로 자동 재개하지 않는다. C와 착용 상태를 필요한 경우 다시 확인하고 **명시적 재개**를 누른다. 앱 비활성화로 세션이 종료된 경우 같은 저장 공간을 다시 불러와 C를 검증해야 한다. 같은 실행 중 동일 저장 공간으로 복원하면 일시정지했던 목적지 번호를 유지한다. 강제 종료 후에는 p0에서 새 안내를 시작한다.

## 저장 파일과 로그

`Documents/Scans/<UUID>/`에 `worldmap.bin`, `mesh.json`, `manifest.json`을 저장한다. `manifest.json` v2는 기존 O/F 파생 기준 앵커 및 독립 C와 함께 **원본 네 꼭짓점, 검증된 직사각형 E, 무대 정면, 순서 있는 p0~p5, 장애물 바닥 영역·종류·통과 정책, 실험 설정**을 포함한다. 지도·메시는 SHA-256으로 검사하고, 기존 v1 저장본은 읽을 수 있지만 경로 안내 대상이 아니다. 공간 지도 로드와 C 검증은 별개다.

`Documents/Trials/trial-<UUID>.jsonl`은 프레임 위치·정면, 추적 상태, C 오차, 착용 시작·중단, 수신된 원격 명령, 경로 안내·일시정지·완료, 수동 실측 메모를 기록한다. 저장 실패 시 측정을 멈춘다. `verified=false` 표본을 정확한 위치로 해석하지 않는다. 저장 지도만으로 **미등록 물체나 이동한 장애물을 감지할 수 없다**. 공연 전 물체 배치가 달라졌다면 영역과 경로를 다시 확인해야 한다.

## 실기기 평가 순서 — 아직 미실시

통제된 평지에서 동행 검증자와 수행한다. 경계/장애물을 가로지르는 잘못된 경로는 화면에서 차단만 확인하고 실제로 걷지 않는다.

- [ ] LiDAR iPhone 모델·iOS, 에어팟 모델·펌웨어, 거치대·의상, 조명·무대 크기와 실제 p0~p5 표식 위치를 기록한다.
- [ ] 네 꼭짓점을 여러 번 선택하고 줄자·수평 측정과 비교해 E 크기·정면·원본 잔차를 기록한다. 잘못된 순서·한 점 수정·높이 다른 표면 선택을 시험한다.
- [ ] 박스와 계단의 여러 면이 메시·독립 3D 보기에 표시되는지, 수동 영역과 실제 점유 범위가 맞는지 확인한다. 등록 장애물을 이동시키면 재등록 전에는 감지하지 못함을 확인한다.
- [ ] 경계 접촉, 물체 관통·접촉·여유 경계, 수정 후 재검사, 계단 통과 차단을 확인한다.
- [ ] 앱 강제 종료 → 저장 공간 복원 → 실제 C 재선택 시간을 최소 3회 기록한다. 일부러 잘못 선택한 C가 차단되는지 확인한다.
- [ ] 후면 카메라가 앞을 향한 배 착용에서 정면/오른쪽/뒤/왼쪽 자세 오차와 폰 위치 대 발 표식 오프셋을 줄자로 측정한다.
- [ ] 화면 시작, 카운트다운, p0 밖·정면 오차·추적 불량 시작 차단을 확인한다. 에어팟 play/pause/toggle이 실제로 전달되는지 모델별로 기록하고, 미전달 시 화면 버튼을 사용한다.
- [ ] 직진·옆걸음·뒷걸음·회전, 경로 교차·다른 목적지 근접에서 8방위와 p1~p5 순서를 확인한다. 도착 반경·체류시간의 잘못된 진행률을 기록한다.
- [ ] 추적 가림, 화면 비활성화, 오디오 중단 후 음성 중지·자동 재개 금지·C 재검증·명시적 재개를 확인한다.
- [ ] 최소 3회 반복하여 위치·방향 오차, 잘못된 도착, 복원 시간, 발열·배터리·프레임 저하와 공유 JSONL을 기록한다.
