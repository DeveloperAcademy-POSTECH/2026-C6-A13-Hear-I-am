# 저장된 무대의 벽·커튼 색상

- 브랜치: `codex/scan-surface-colors` (`develop`에서 분기).
- 범위: 새 LiDAR 스캔의 주변 수직 표면 색상을 수집하여 공연/공간 폴더의 저장된 무대 화면에 표시.
- 바닥의 오크 텍스처, 등록 기물, 원본 스캔 보기, 일반 미리보기, 사진 비교, 실제 이동 기록 재생은 기존 표현을 유지한다.

## 수집과 저장

`SessionBridge`의 AR delegate 큐에서 최대 초당 두 번 카메라 YCbCr, sceneDepth, confidence를 복사한다. 지원 기기에서는 사람 분할 마스크도 사용한다. 빠른 이동/회전, 추적 제한 프레임은 건너뛴다. 원본 ARFrame/CVPixelBuffer를 보관하지 않고 최대 160픽셀 변의 작은 관측 48개만 메모리에 유지한다. 깊이는 정수 stride로 원본 픽셀을 선택한다(예: 256×192 → 128×96). RGB는 그 깊이 픽셀의 대응 광선 위치에서 가져오며, intrinsics는 원본 깊이 해상도/stride에 맞춰 스케일한다. 일반 이미지 리사이즈용 half-pixel 이동을 섞지 않는다. 사람 마스크는 해당 축소 셀의 픽셀 중 하나라도 사람일 때 보존한다. 관측 선택에는 깊이·신뢰도·사람 마스크·각도를 통과한 수직 표면의 35cm 공간 구간을 사용한다. 같은 구간을 0.3초 이상 간격으로 보고 색이 일치하는 두 관측의 보존을 우선한다. 공간 구간은 영상 선택용 근사치이며 실제 채색의 안전 검사를 대체하지 않는다. 용량이 가득 차도 처음 보는 벽의 첫 관측이 다음 관측과 짝을 이룰 기회를 갖도록 새 구간을 담은 최신 영상 한 장의 수용을 우선한다. 같은 보존 가치에서는 중복 시점의 오래된 관측을 제거한다. 48장 상한 때문에 모든 벽의 두 관측을 보장하지는 않는다.

각 관측에 임시 ARAnchor를 연결한다. 저장할 때 최종 메시와 관측 앵커의 포즈를 같은 스냅샷에서 가져온다. ARWorldMap에 메시가 있으면 그 스냅샷을 사용하고, 없으면 세션 정지 후 currentFrame의 메시와 앵커를 함께 사용한다. 저장 중 busy 상태 때문에 갱신이 멈춘 UI 메시 캐시와 새 카메라 포즈를 섞지 않는다. 같은 스냅샷의 메시를 모두 복사하지 못하면 기존 캐시 형상 저장은 유지하되 카메라 채색을 비활성화한다. 메시 갱신 전후의 정점 번호가 같다고 가정하지 않는다. 색상 계산은 UI 스레드 밖에서 수행한다. 폴더의 바닥 재질·바닥 채색 제외·경로 기준은 그대로 유지하며, 새 스캔의 메시만 저장 시점 스냅샷으로 갱신한다. 임시 관측 앵커는 보관용 world map에서 제거하며 카메라 관측 영상은 디스크에 저장하지 않는다. 성공/세션 종료 시 관측 메모리를 해제한다.

수직에 가까운 면(`abs(normal.y) / length < 0.65`)에만 색상을 계산한다. 카메라 앞 0.25~5m, 정면성, 깊이 오차, 중간 이상의 깊이 신뢰도 및 사람 마스크로 관측을 거른다. 3×3 중 중심을 포함한 6개 이상의 깊이가 일치해야 한다. 정보가 없는 주변 픽셀만 최대 3개 제외할 수 있으며, 중심 정보 누락·사람 마스크·신뢰할 수 있는 전경/배경 깊이 불일치는 하나라도 있으면 관측 전체를 거부한다. 기울어진 벽은 각 픽셀 광선과 국소 표면 평면의 교점 깊이를 비교하며 오차 허용폭 자체는 늘리지 않는다. 0.3초 이상 떨어진 두 개 이상의 관측이 색상에 동의해야 채색한다. 지나치게 클리핑된 검정/흰색은 제외하되 낮은 밝기의 커튼은 허용한다.

`MeshSnapshot.surfaceColors`는 선택적 RGBA8 Data 필드다. RGB는 sRGB, alpha 0은 미관측, 255는 관측 완료다. 기존 `mesh.json` 해시 검증과 저장 원자성을 그대로 사용한다. 기존 JSON에 필드가 없으면 nil로 디코딩되므로 기존 스캔을 재저장하거나 마이그레이션하지 않는다. 색 데이터의 길이와 alpha 값을 검증한다.

`MeshSnapshot.inferredSurfaceColors`는 직접 관측 색과 분리된 선택적 RGBA8 배열이다. 직접 관측의 alpha가 0인 정점에만 추정 색을 저장할 수 있으며 두 배열의 길이·alpha·중복을 검증한다. `displaySurfaceColors`는 표시할 때만 두 배열을 합친다. 이전 앱의 관측 색은 그대로 직접 관측으로 취급하고, 색이 없던 기존 스캔에는 새로운 색을 생성하지 않는다.

## 위쪽의 작은 미관측 구간 보완

새 스캔의 직접 색상 계산 뒤, 아래쪽 직접 관측을 사용해 같은 메시 안의 가까운 위쪽 구간만 추정한다.

- 기준 관측점보다 위로 최대 30cm, 표면의 좌우 방향 ±18cm 안에서 찾는다.
- 중력 기준 수직에 가까운 표면이어야 한다. 기존 10도 면 방향 검사를 먼저 적용한다. 실패한 정점은 면적 85% 이상을 차지하는 두 개 이상의 면으로 지지되는 우세 평면을 확인한다. 주변 모든 꼭짓점의 평면 오차가 8mm 이하이고, 별도의 일관된 두 번째 면 그룹이 없을 때에만 고립된 작은 삼각형의 법선 흔들림을 허용한다. 실제 두 평면의 모서리·접힘·단차는 차단한다. 탐색 중 방향 차이 10도와 기준 평면 거리 2cm 제한도 유지한다.
- 최소 3개의 직접 관측점이 필요하며, 아래쪽 두 높이(4cm 이상 차이)와 대상의 좌우 양쪽에서 지지해야 한다.
- 연결된 국소 영역의 모든 직접 관측 색이 서로 비슷해야 한다(sRGB 벡터 거리 0.10 이하). 다른 색을 소수 이상치로 버리지 않는다. 같은 높이나 바로 위쪽에서 발견한 다른 관측 색도 경계로 취급한다.
- 서로 다른 평면이 공유하는 모서리는 통과하지 않는다. 끊긴 메시, 서로 다른 AR 앵커, 25cm를 넘는 메시 변도 건너지 않는다. 주변 탐색이 256개 정점을 넘으면 보완을 포기한다.
- 사람 마스크·전경/배경 깊이 불일치·클리핑·색상 충돌·관측 시간 간격 부족은 계속 보완을 차단한다. 한 번의 유효 관측만 있는 정점은 다른 위험 신호가 없고 주변 직접 관측 색과 일치할 때에만 추정으로 보완한다. 대상뿐 아니라 탐색 경로의 단일 관측 색도 경계 판정에 포함한다. 단일 관측은 직접 관측 색이나 아래쪽 지지점으로 승격하지 않는다. 직접 관측으로 최종 확정된 정점은 그대로 유지한다.
- 추정 색은 다른 정점의 근거로 쓰지 않는다. 재실행해도 추정만으로 높이 제한을 넘어 연쇄 확장하지 않는다.
- 직접 관측점의 공간 인덱스로 가까운 근거가 없는 큰 미관측 영역은 탐색 전에 제외한다.

이 절차는 관측하지 못한 부분의 실제 색을 보장하지 않는다. 단색·동일 평면이라는 가정이 확인되는 가까운 구간에 한정한 표시용 추정이다. 메시에 잡히지 않은 벽을 새로 만들지 않고, 바닥·동선·기물 형상도 바꾸지 않는다. 기존 저장 파일을 열 때 다시 추정하지 않는다.

## 누락 진단과 동일 입력 비교

새 스캔을 저장하면 스캔 디렉터리에 `surface-colors.json`을 함께 기록한다. 렌더러와 안내는 이 진단 파일을 읽지 않는다. 기존 스캔에는 파일을 추가하지 않는다. 집계에는 이미지·위치·카메라 포즈가 없으며, 다음 수치만 포함한다.

- 유효/무효 관측 프레임 수, 채색 대상/완료 정점 수.
- 정점×프레임 관측 시도 수, 성공 수, 6~8개 이웃으로 받아들인 관측 수.
- 최초 거부 원인별 수: 범위 밖, 비스듬한 시선, 화면 밖, 사람 마스크, 중심 깊이 없음, 전경 가림, 다른 깊이, 이웃 부족, 색 클리핑.
- 정점 색상 누락 원인: 유효 관측 부족, 색상 불일치, 관측 시간 간격 부족. 버전 3의 `observationCounts`는 유효 관측 0회/1회/2회 이상을 별도 집계한다.
- 버전 3의 `capture`는 수집 시도, 추적·움직임·복사 실패, 수집·퇴출·최종 유지·보정 앵커 누락 수를 기록한다. 구간/관측 쌍 수는 보정 전 수집 좌표계의 보존 지표이며 최종 메시 채색률과 다르다. 선택 총 소요 시간과 최대 소요 시간(ms)은 비교용 이전 정책의 실행 시간을 제외한다.
- 실제 폴더에 남는 수직 표면의 삼각형 수/면적과 채색 수/면적. 바닥과 등록 기물로 대체된 표면은 제외한다. 버전 3의 `directColoredTriangles`와 `directColoredAreaSquareMeters`는 추정 없이 완성된 삼각형을 별도로 집계한다.
- 꼭짓점 1/2/3개 누락 때문에 회색으로 남는 삼각형 수.

`surface_color_bake` 진단 로그 이벤트에도 요약을 남긴다. Debug 실행의 Xcode 콘솔에서는 `SURFACE_COLOR_REPORT`로 찾을 수 있다. Scheme → Run → Arguments에 `--surface-color-compare`를 추가하면 같은 카메라 입력 스트림에 이전 시점 다양성 정책의 별도 버퍼(최대 48장)를 함께 적용한다. 저장할 때 같은 최종 메시와 보정된 포즈로 이전 단일 관측 차단·엄격 평면 판정도 계산하여 `SURFACE_COLOR_BASELINE`을 출력한다. 두 경로 모두 6/9 주변 픽셀 판정을 사용하므로 이번 관측 보존·상향 보완 변경을 비교할 수 있다. 이 옵션에서만 두 버퍼 합계 최대 96장과 추가 저장 계산 비용이 발생하며 새 정책 결과만 저장한다. 일반 Debug/Release는 48장 제한을 유지한다. 각 관측 앵커는 두 버퍼 모두에서 빠졌을 때 제거하고 저장 world map에는 남기지 않는다. 코어의 `.strict` 9/9 정책은 기존 이웃 완화 회귀 테스트용으로 유지한다.

사람 마스크는 낮은 깊이 신뢰도와 분리된 배열로 전달한다. 사람을 단순한 깊이 누락으로 오인하여 무시하는 회귀를 방지한다. 진단 보고서 버전 2의 `upperFill`에는 보완 후보/추정 정점 수, 거부 원인, 추정이 포함된 표시 삼각형 수와 면적을 별도로 기록한다. `coloredVertices`는 직접 관측 정점 수이며, 전체 채색 면적에는 추정이 포함된다. 버전 3의 `upperFill.blockedReasons`는 사람·전경·깊이·클리핑·색상·시간 충돌을 정점 단위로 분리한다. 한 정점이 여러 이유에 해당할 수 있으므로 이 세부 합계는 차단 정점 수와 같지 않을 수 있다. `singleObservationCandidates`/`singleObservationFills`는 단일 관측 후보·실제 보완 수, `recoveredPlaneVertices`는 작은 삼각형 법선 흔들림에서 회복한 정점 수다. 후자는 실제 채색 완료 수와 다르다. 이전 진단 파일의 `upperFill` 및 새 선택적 필드 부재도 허용한다.

## 깊이 충돌 진단 (버전 4)

색상·추정의 합격/거절 조건은 바꾸지 않는다. 기존 깊이 검사에서 최초 거절이 결정된 뒤에만 같은 3×3 영역을 추가 조사한다. 진단 결과를 색상 수락이나 보완 허용에 사용하지 않는다. `surface-colors.json`과 `SURFACE_COLOR_REPORT`에 `depthAnalysis`가 자동으로 추가되며 실행 옵션은 필요 없다. 집계만 저장하므로 이미지·포즈·정점 좌표를 추가로 보관하지 않는다. 기존 보고서에 이 필드가 없으면 nil로 읽는다.

- `firstFailureLocation` / `firstFailureReason`: 최초 거절이 중심/이웃 중 어디서 발생했고 기존 판정이 전경/깊이 불일치 중 무엇인지. 한 정점×영상마다 한 번만 센다.
- `firstResidualMagnitudeMeters`: 측정 깊이와 해당 픽셀 광선-메시 평면 교점 깊이의 차이 절댓값. ≤10cm, 10~20cm, 20~50cm, >50cm를 구분한다.
- `firstExcessOverToleranceMeters`: 기존 허용폭(3.5cm + 예상 깊이의 1.5%)을 넘긴 양. ≤2cm, 2~5cm, 5~15cm, >15cm를 구분한다. 예상 깊이가 유효하지 않으면 두 히스토그램 모두 `invalidPrediction`에 기록한다.
- `firstFailureConfidence`, `cameraDepthMeters`, `viewingAngle`: 최초 실패 픽셀의 깊이 신뢰도, 카메라 Z 깊이 구간, 정면성 구간. 정면성은 기존 내적 기준 ≥0.85/≥0.6/그 미만(기존 최소 0.4를 통과한 범위)이다.
- `footprintPatterns`: 예상 깊이 계산 불가 → 한 영역 안의 앞뒤 혼재 → 중심은 일치하고 이웃만 충돌 → 6개 이상이 앞/뒤로 치우침 → 그 외 일부 픽셀의 앞/뒤 충돌 순으로 배타적으로 분류한다. 6개 이상 치우친 경우 유효한 잔차 절댓값의 중앙값 ≤15cm를 `SmallOffset`, 그보다 큰 값을 `LargeOffset`으로 기록한다. 이 15cm는 진단 분류용일 뿐 허용 오차가 아니다.
- `reliablePixelsPerFootprint`: 깊이가 양수·유한하며 confidence ≥1인 픽셀 수. 이 신뢰도는 센서의 값이지 실제 물체 판정의 보장이 아니다.
- `framesWithPersonMask` / `framesWithoutPersonMask`: 사람 마스크를 사용할 수 있었는지 확인한다. 사람 마스크 거절은 기존 `rejectedObservations.personMask`에 남으며 깊이 오차로 다시 분류하지 않는다.
- `conflictViewsPerVertex`, `acceptedViewsAtConflictedVertices`: 같은 정점에서 충돌한 영상 수와 정상 수락 관측 0/1/2회 이상. 다른 시점에서 정상으로 보이는지 구분한다.
- `signPatternsAcrossViews`: 한 영상 내 앞뒤 혼재, 영상 사이 부호 변화, 앞쪽만, 뒤쪽만, 예상 깊이 계산 불가만으로 분류한다. 한 영상 내 혼재를 먼저 적용한다. `uncoloredAcceptedViews`, `uncoloredSignPatterns`는 직접 색 확정에 실패한 정점만 집계한다. `directVerticesWithDepthConflict`는 다른 관측의 증거로 직접 색이 확정된 정점이다. 정점 집계는 채색 대상 메시 전체 기준이며 폴더 표시 면적과 분모가 다르다.

`mostlyNearLargeOffset`은 실제 앞쪽 물체와 양립하는 패턴이고, 작은 잔차·부호 변화·중심 일치/이웃 충돌은 깊이·포즈·메시 또는 경계 오차와 양립하는 패턴이다. 어느 것도 실제 원인을 확정하지 않는다. 실제 물체, 커튼의 움직임, 깊이 측정 오차가 같은 패턴을 만들 수 있다. 확인 스캔은 기본 무대 등록 과정을 유지하면서 가림 없는 단색 벽 한 구간을 정면에 가깝게 아래→위로 겹쳐 비추고 저장한다. 벽 앞 기물이 있는 비교 스캔은 별도로 저장해 진단을 비교한다.


## 좌표 정렬 점검 및 수정 (버전 5)

Apple 공식 [scene depth point cloud 샘플](https://developer.apple.com/documentation/arkit/displaying-a-point-cloud-using-scene-depth)의 원본 깊이 픽셀 좌표와 해상도 비율 intrinsics 스케일을 확인했다. 카메라의 -Z 전방/+Y 위쪽, 센서 영상의 +Y 아래쪽, 메시의 column-major local→world 및 inverse camera 투영은 유지한다.

확인된 문제는 두 가지다. 첫째, 임의 비율 최근접 축소에서 depth와 RGB가 각각 반올림되어 다른 광선을 선택할 수 있었고, 일반 이미지 리사이즈의 half-pixel 보정을 depth intrinsics에 사용했다. 이제 정수 stride로 실제 깊이 광선을 선택하고 RGB·intrinsics를 같은 광선에 맞춘다. 원본 camera.imageResolution과 실제 RGB 버퍼 크기가 다르면 추측해서 채색하지 않고 관측을 제외한다. 둘째, busy 동안 UI 메시 캐시는 갱신되지 않았지만 색 관측과 앵커는 갱신될 수 있었다. 이제 최종 메시와 포즈를 같은 world-map/current-frame 스냅샷에서 복사한다.

`alignment`에는 raster 정책, 메시 출처(`worldMap`/`currentFrame`/`cacheWithoutColors`), 최종·캐시 메시 수, 새로 추가되거나 사라진 메시, 형상이 변경된 메시 수, 메시 transform의 최대 위치 차이, 원래 카메라 포즈와 최종 관측 앵커 포즈의 위치·회전 차이를 기록한다. 이는 좌표 보정의 관측값이며 실제 벽과의 정확도를 보장하지 않는다. 관측 앵커를 역사적 카메라 포즈의 완벽한 재최적화 결과라고 가정하지 않는다. 이전 버전 진단은 `alignment` 없이 읽을 수 있다.

중심/이웃 충돌과 큰 깊이 오차의 수치·허용폭·사람 및 기물 차단 조건은 유지한다. 축소 마스크는 더 보수적으로 사람 픽셀을 보존한다. 합성 검증에서는 원본 깊이 광선과 RGB 위치가 일치하고, 같은 평면의 이웃 깊이가 맞으며, 실제 전경 픽셀은 계속 거절된다. 카메라만 0.8m 보정하고 메시를 갱신하지 않은 경우 큰 깊이 차이가 재현되고, 둘을 같은 좌표계로 맞추면 원래 직접 색이 복구된다. 이 재현이 실기기의 모든 50cm 이상 오차 원인을 증명하지는 않는다. 원본 관측 영상을 저장하지 않았으므로 과거 스캔을 새 정렬로 소급 계산하지 않는다. 기존 스캔·바닥 표시·가림 역치 변경은 없다.

기존 `--surface-color-compare`는 보존/상향 보완 정책 비교다. 양쪽 모두 새 픽셀 정렬과 동일한 최종 스냅샷을 사용하므로 이번 정렬 수정의 이전/이후 비교는 새 스캔 진단과 함께 별도로 해석해야 한다.


## 화면

폴더의 immersive renderer만 색상을 사용한다. 주변 면을 관측 완료/미완료 삼각형으로 나눠, 세 정점 모두 관측된 수직 면에만 색상을 적용한다. 미완료 면과 이전 스캔은 기존 회색 재질을 유지한다. 바닥 판정/평탄화/오크 재질에는 색상을 전달하지 않는다.

SceneKit 정점 색상에는 sRGB를 linear RGB로 변환해서 전달한다. 촬영 당시의 조명이 이미 색에 포함되어 있으므로 색상 표면은 constant 재질을 사용하고 기존 푸른 multiply 보정에서 제외한다. 이 처리가 없으면 검정·채도 높은 색이 과도하게 밝아진다.

## 실기기에서 확인할 항목

전체 무대를 두 번 도는 것보다 같은 벽을 정면에 가깝게 1~2초 안정적으로 보고, 겹치는 구간을 유지하며 옆·위쪽으로 이동한다. `--surface-color-compare`를 켠 새 스캔에서 직접 관측 면적과 추정 면적을 따로 비교한다. 오래된 스캔에는 원본 관측 영상이 없으므로 새 선택 정책을 소급 비교할 수 없다.

시뮬레이터는 실제 LiDAR 수집 품질을 검증하지 못한다. 밝은 일반 조명에서 흰 벽·붉은 커튼·검은 커튼을 잠시 멈춰가며 비추고 저장/재열람한다. 벽 앞을 지나가는 사람의 색이 남지 않는지, 바닥이 그대로인지, 세로/가로 촬영과 장시간 스캔, 앱 중단·재개·저장 재시도가 정상인지 확인한다. 스캔 중 프레임률/발열과 저장 시 계산 시간을 측정한다.

색은 재질의 고유색이 아니라 촬영 당시 보이는 색이다. 어두운/흡광성 커튼, 움직이는 커튼, 깊이가 없는 부분, 멀거나 가려진 부분은 회색으로 남을 수 있다. 정점 사이 색상 보간이므로 고해상도 무늬·섬유 질감을 재현하지 않는다. 기존 스캔의 자동 소급 채색과 실제 이동 기록에 벽을 추가하는 작업은 포함하지 않는다.
