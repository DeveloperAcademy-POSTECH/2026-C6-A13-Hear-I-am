## 이번에 구현한 범위

저장 공간을 열면 `스캔 보기`가 기본으로 나온다. 기존의 어두운 배경·회색 원본 메시·청록색 무대 경계·빨간 기물 영역·노란 확인점·주황색 인물 표시를 사용한다. 전체 시점은 무대 경계 밖의 스캔 영역까지 포함하며 표면 선을 켤 수 있다. `정리해서 보기`의 현재 구현은 등록한 무대와 기물을 무광 기본 모형으로 보여준다. 아래 승인된 디자인의 재질·공간 정리는 아직 적용 전이다.

- 전체와 동선 위에서, 두 가지 빠른 카메라 시점. 핀치로 직접 확대할 수 있다.
- 시점을 바꿀 때 이전 카메라의 회전 축과 관성을 이어받지 않으며, 전체→위→전체 왕복 후 같은 전체 구도로 돌아온다.
- 번호와 진행 방향이 있는 동선. 지점을 선택하면 인물 모형이 해당 위치와 다음 방향을 표시한다. 마지막 점에서는 직전 구간 방향을 사용한다.
- 기물 선택 시 카메라를 이동시키지 않고 등록된 바닥 영역과 상세 정보를 표시. 화면 안 모형 터치와 하단 목록 모두 지원한다.
- 의자·테이블·보면대·마이크·스피커·바닥 모니터의 임시 모형. 기본 입체·단상·계단은 등록된 다각형을 사용한다.
- 기물 등록 단계에서 표시 모형과 객석 기준 방향을 선택한다. 기존 통행 정책과 충돌 영역은 별도로 유지한다.
- 인물은 등록된 동선을 설명하는 표시다. 실제 사람 감지나 녹화된 이동 위치가 아니다.

## 사진을 남기는 흐름

1. 무대 준비 중 추적이 정상일 때 `사진 남기기`를 누른다. 자동 연속 촬영은 하지 않는다.
2. 실행 중인 ARSession의 현재 프레임에서 이미지와 카메라 위치·방향·시간을 함께 가져온다. 별도 카메라 세션을 켜지 않는다.
3. 같은 위치에 ARAnchor를 추가한다. 최종 공간 지도의 앵커 좌표로 촬영 위치를 갱신해 메시와 같은 좌표계를 사용한다.
4. 메인 화면 작업과 분리해 화면 방향을 보정하고 JPEG와 썸네일을 만든다. 최대 긴 변 1600px, 썸네일 320px이며 공간당 40장까지다.
5. 준비 중에는 임시 파일로 보관한다. 사진 목록에서 등록된 기물이나 동선 지점을 연결하거나 연결을 해제하고 삭제할 수 있다.
6. 공간 저장 시 지도·메시·사진·촬영 정보를 하나의 묶음으로 저장한다. 중간 실패 시 완성되지 않은 저장 묶음은 제거하고 준비 중 사진은 재시도를 위해 유지한다.
7. 다시보기에서 연결된 기물·지점 선택 시 작은 사진 카드가 나타난다. 카드를 접거나 크게 볼 수 있고, 사진 목록에서 촬영 위치와 방향도 선택할 수 있다.

촬영은 저장 처리와 중복되지 않는다. 추적 중단·화면 종료·세션 교체 뒤에 늦게 돌아온 촬영 결과는 추가하지 않는다. 기물이나 지점을 삭제하거나 새 도면을 적용할 때 예전 사진의 연결을 해제해 새 대상에 잘못 붙지 않게 한다.

카메라 사용 설명에 현장 사진 촬영을 추가했다. 사진은 앱의 저장 공간에 보관하며 사진 보관함 접근 권한을 요청하거나 자동 업로드하지 않는다.

## 저장 및 호환

- `ScanManifest.photos`는 선택적 추가 필드다. 이전 manifest v1/v2에 필드가 없으면 빈 목록으로 읽는다.
- 사진마다 UUID, 촬영 시각, 프레임 시간, 열 우선 4×4 카메라 변환, 보정된 픽셀 크기, 파일 해시, 선택적 기물 ID/동선 인덱스를 보관한다.
- `photos/<UUID>.jpg`, `photos/<UUID>-thumb.jpg`를 공간 묶음 안에 둔다. 이름 변경은 그대로 보존하고 공간 삭제 시 함께 제거한다.
- 파일 크기와 해시를 검사하며 사진은 필요한 시점에만 읽는다. 사진 파일이 없거나 손상돼도 지도·메시 로딩을 막지 않고 해당 사진에 오류를 표시한다.
- `StageObstacle.appearance`가 없는 예전 자료는 기본 입체로 표시한다. 모르는 모형 값도 기본 입체로 읽는다.
- 측정하지 못한 높이는 표시용 기본값을 사용하며 상세 카드에 미측정임을 표시한다. 기본 높이를 실제 측정값으로 저장하지 않는다.
- 계단의 단 수·진입 방향 데이터는 없으므로 임의의 계단을 만들지 않고 영역과 높이만 표시한다.

## 추후 모델을 교체할 때

`ReplayModelFactory`가 모형을 만들고, `ObjectAppearance`와 `ObjectPlacement`가 종류·방향·위치·크기를 제공한다. 실제 에셋을 불러오는 코드를 팩토리에 연결하면 배치·선택·사진 연결을 유지할 수 있다. 현재는 외부 에셋 로더를 추가하지 않았다.

- 단위: 미터, 위쪽: +Y, 바라보는 방향: +Z.
- 원점: 바닥에 닿는 부분의 중심. 모델 원본의 축·원점·실제 크기를 함께 전달한다.
- 텍스처는 은은한 색과 거칠기 위주로 시작한다. 복잡한 재질이나 고해상도 텍스처는 실제 기기에서 성능을 확인한 뒤 적용한다.
- 실제 모델 외형과 등록된 장애물 영역은 다를 수 있다. 안내 판정은 등록 영역을 사용한다.
- 사람이 움직이는 단계에서는 리깅된 모델과 걷기/대기 클립, 실제 기록의 위치·방향·시간 데이터가 추가로 필요하다.

## 나중에 할 것

실제 3D 에셋과 텍스처 적용, 사진을 메시 표면에 투영하는 작업, 촬영 품질에 따른 자동 사진 추천, 리깅·걷기 애니메이션, 실제 이동 기록의 시간축 재생은 이번 범위에 포함하지 않았다. 현장 사진은 참고 카드이며 메시 텍스처로 사용하지 않는다.

## 승인된 정리해서 보기 디자인 (2026-10-20)

사용자는 첫 번째 원본 스캔 화면을 기준으로 만든 UI 이미지의 방향을 승인했다. 무대 영역만 평면으로 떼어내지 않고 주변 바닥·벽·기물까지 같은 공간으로 이어서 정돈한다. 바닥은 낮은 대비의 타일 무늬와 은은한 색, 벽은 단정한 면, 기물은 형태를 알아볼 수 있는 모형과 절제된 재질을 사용한다. 동선·무대 경계·인물의 위치와 방향은 유지한다.

이 이미지는 디자인 시안이다. 원본 회색 메시에서 실제 바닥 색·재질이나 소파 종류를 복원한 결과가 아니다. 현재 저장 데이터에는 표면 분류·재질 정보가 없으므로, 실제 적용 시 스캔에서 추정한 면과 사용자가 지정한 기물/재질을 구분해야 한다. 준비하지 않은 영역이나 불확실한 형상을 임의로 실내 모형으로 채우지 않는다. 실제 3D 기물은 사용자가 제공할 에셋으로 교체할 수 있게 한다.

## 실제 기기 확인 순서

사용자 실기기 확인으로 카메라 왕복 회전 문제와 주황색 메시 회귀를 발견했다. 해당 수정의 실기기 재검증과 아래 나머지 항목은 미실시다.


- [ ] 기존에 저장한 공간을 열어 사진이 없어도 정리/스캔 보기와 동선이 표시되는지 확인.
- [ ] 가로 양 방향에서 사진을 촬영하고 결과의 위아래와 색이 실제 카메라 화면과 맞는지 확인.
- [ ] 추적이 불안정한 동안 촬영 버튼이 비활성화되고 정상 복귀 후 촬영되는지 확인.
- [ ] 촬영 중 뒤로 가기·백그라운드 이동·준비 재시작 시 이전 사진이 다음 세션에 섞이지 않는지 확인.
- [ ] 새 기물을 등록하고 종류·방향을 고른 뒤 사진 연결·해제·삭제, 지점 삭제 후 새 지점 생성 시 연결이 유지되지 않는지 확인.
- [ ] 사진 직후 최종 저장과 저장 실패 재시도, 앱 재실행 후 공간·사진·촬영 위치 보존 확인.
- [ ] 전체→위→전체 반복 전환, 카메라, 모형 터치, 회전·이동·확대, 사진 카드 접기·확대·목록 선택 확인.
- [ ] 단상 위 지점을 선택했을 때 인물의 발이 측정된 단상 높이에 놓이는지 확인.
- [ ] 40장 촬영 시 제한과 큰 공간에서 메모리·발열·프레임 유지 확인.
- [ ] VoiceOver와 큰 글씨에서 기물·지점 목록, 사진 촬영·선택·닫기 동작 확인.
