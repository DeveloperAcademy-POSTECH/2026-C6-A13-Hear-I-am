# PoC3 구현 계획

작성: 2026-10-11. 구현 시작 전에 작성한 계획.

## 목적

StageVision_iphone의 1인 이동 PoC를 기반으로 무대 스캔, 무대 정면 설정, 시작점 P와 목적지 D 설정, 배에 착용한 iPhone의 몸 방향 측정, 폰 스피커 음성 안내를 결합한다. 새 프로젝트는 `PoC3/PoC3.xcodeproj`로 만든다.

## 확인한 기존 구조

- StageScanController가 스캔과 사람 추적에 같은 ARSession을 유지한다.
- 무대 좌표는 +X 오른쪽, +Y 무대 뒤쪽, 정면/객석은 (0, -1)이다.
- 기존 실측 위치는 운영자 기기의 Vision + LiDAR 몸통 투영 좌표다.
- 기존 StageBeaconAudio는 AirPods 머리 방향과 공간음향에 의존하므로 새 스피커 안내기로 대체한다.
- orientation-haptics는 Core Motion rotationMatrix의 화면 바깥쪽 +Z 벡터를 수평면에 투영한다. 리셋 기준 상대 회전을 측정하며 절대 무대 방위를 자동으로 알지 못한다.
- 화면 바깥쪽 배 착용 시 후면 카메라는 몸을 향한다. 같은 폰으로 기존 외부 촬영 위치 추적을 계속할 수 없다.

## 기기 구성 결정

사용자 확인 완료: 운영자 스캔/추적 기기 + P 착용 폰 2대 구성으로 구현한다. 같은 앱에서 역할을 선택한다. MultipeerConnectivity 암호화 세션을 사용하고, 착용 폰에 표시된 연결 코드를 운영자 기기에 입력해 상대를 선택한다.

운영자는 기존 세션으로 P 위치를 측정하고 착용 폰과 로컬 연결한다. 착용 폰의 상대 방향을 무대 정면과 명시적으로 보정한다. 위치와 목표는 착용 폰으로 전달하고 안내는 착용 폰 스피커에서 출력한다.

## 구현 순서

1. 별도 PoC3 프로젝트 생성. 기존 수정/미추적 파일은 그대로 유지하고 필요한 스캔·기하·추적 코드를 복사해 독립 실행한다.
2. 몸 방향 계산·보정 및 P→D 상대각 계산을 기기 API와 분리한다. 무대 정면 보정, 좌우 부호, ±180° 경계, 센서 만료를 테스트한다.
3. 확정된 기기 구성의 위치 입력을 연결한다. 스캔 정면과 착용 정면은 P가 객석을 향해 선 상태에서 보정한다.
4. 시작점/목적지 지정 → 몸 정면 보정 → 안내 시작 → 회전/전진 → 도착 흐름 구현. 목적지 변경·추적/연결 중단은 이동 안내를 정지한다.
5. 폰 스피커 한국어 음성: 목표 상대각에 따라 왼쪽/오른쪽 회전, 정렬 시 전진 및 남은 거리, 도착 시 정지 안내. 반복 발화 제한, 오래된 발화 취소, 앱 중단/출력 경로 변화 처리.
6. 센서 없는 조작 예제, 연결/센서 상태, 운영자와 착용자 화면, VoiceOver 레이블 제공.
7. 호스트 계산 테스트, iOS Simulator 및 device 서명 제외 빌드, 실행 가능한 범위의 화면 확인. 실제 무대·두 기기·착용·음성 출력 검증은 별도 체크리스트로 남긴다.

## 범위

단일 P, 무대 안의 직선 이동을 먼저 구현한다. 경계 밖으로 나가는 직선은 거부한다. 장애물 회피·다인 추적·자동 경로 계획·공연 수준 위치 정확도 보장은 포함하지 않는다. 착용 밴드 움직임과 상대 방향 drift는 현장 재보정 대상이다.

## 확정 설계

- 운영자: 스캔과 P 추적을 동일 ARSession에서 계속한다. 현재 P 위치를 시작점 S로 확정하고 D를 지도에서 선택한다. P를 객석 방향으로 정렬한 뒤 정면 보정을 요청한다.
- 착용 폰: Core Motion 화면 +Z의 상대 회전을 무대 정면 (0,-1)에 결합한다. 목적지까지 상대각/거리로 한국어 음성을 생성한다. 공간음향 팬 대신 명시적 좌우 회전 문구를 사용한다.
- 통신: 착용 폰이 짧은 주기로 요청 ID를 보내고 운영자가 현재 위치/지도/목표/보정 세대/실행 세대를 응답한다. 기기 uptime을 직접 비교하지 않고 요청 왕복 시간과 운영자 측 측정 나이를 합산해 만료한다. 뒤늦은 응답과 역순 응답을 버린다.
- 연결 단절, 자세 불량, 백그라운드 전환, 음향 중단, 추적 만료 후에는 명시적인 재시작을 요구한다. 목적지/시작점 변경 시 보정을 다시 한다.

## 카메라 오버레이 표시 개선

무대 그리드를 25cm 간격의 얇은 회색 점선으로 변경한다(큰 무대에서는 기존 선 수 제한에 따라 간격 확대). 격자 점선은 단일 선 geometry로 합쳐 노드 증가를 억제한다. 무대 경계는 실선으로 유지하고 S/D 바닥 고리·수직 표시선·S→D 경로는 점선으로 표시한다.

검증: iPhone 서명 제외 빌드 성공. 실제 카메라 화면의 가독성은 미검증이다.

## 보폭 기반 거리 안내 계획

착용자/예제에 미터·걸음 수 선택과 cm/m 단위의 한 걸음 길이 입력을 추가한다. 초기값은 60cm이며 사용자가 실제 측정값을 적용할 수 있고 선택/보폭은 저장한다. 입력은 10~200cm의 유한한 양수만 허용한다. 걸음 수는 실측 남은 거리를 보폭으로 나눈 정수 부분(최소 1), 한 걸음 미만은 작은 걸음 안내로 표현한다. 방향 안내·도착 반경·연속 도착 판정은 기존 로직을 유지한다. 환산/입력 검증 회귀 검사와 빌드를 확인한다.

구현 완료: 착용자/예제 설정, 보폭 저장·유효성 검사, 걸음 안내와 화면 문구 일치를 반영했다. 보폭 관련 20개를 추가하여 총 112개 검사 통과, iPhone 서명 제외 빌드 성공. 실제 보행·음성 청취는 미검증이다.

## 8방위 음성 옵션

각도/시계 방향에 8방위를 추가한다. 이동 안내는 기존 시계 안내와 같이 현재 몸 정면을 북, 오른쪽을 동으로 삼는 상대 방위다. 현재 몸 방향 듣기는 무대 정면을 북으로 삼는 별도 기준을 문구에 명시한다. 45도 간격으로 분류하고, 북으로 반올림되더라도 회전이 필요한 각도에서는 좌/우 미세 조정을 유지한다. 기존 보폭·도착·출력 설정과 함께 사용할 수 있도록 검사한다.

완료: 선택 UI·저장·8방위 발화·현재 방향 읽기를 반영했다. 총 129개 검사 통과, iPhone 서명 제외 빌드 성공. 실제 기기 청취는 미검증이다.
